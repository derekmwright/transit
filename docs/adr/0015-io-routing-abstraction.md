# ADR 0015: I/O routing abstraction: a device channel map, named paths, one route graph

- **Status:** accepted 2026-10-21 (direction pre-approved by the project owner; refutation review round 1 resolved)
- **Date:** 2026-10-21
- **Implementation:** none yet. Slice 0 and slices (a) to (e) below, each shippable. Slice 0 and (a) are not MIDI-path work, so they are sequenced after the live MIDI work.
- **Reopen when:** a slice's gate proves unmeasurable on the reference machine; or upstream SoundCraft lands its own multi-output or sidechain model that we should converge with; or the TASCAM Model 12 shows that device channel counts differ between input and output (or between USB modes) enough that one channel-map shape cannot describe both; or dependency layers for key edges prove too costly in slice (c) (fallback in section 4). WASAPI shared mode exposing one channel count is a stated limit, not a reopen trigger (section 1).

## Context

The project owner asked for that layer to be abstracted to support large custom routing and mixing configurations. Today transit opens output channels 1 and 2 only, and "Out 3-4" goes nowhere. Verified against `soundcraft` branch `transit`, head 6b81c4b (code paths relative to `crates/`):

- **The stream width follows the main bus, not the device.** `Player::prepare`/open asks for `main_channels(&session)` channels (`playback/src/player/device.rs:198`; `LegacyPlayer::open`, `playback/src/lib.rs:774`). `main_channels` is the main format's channel count clamped to 2..=16 (`mix/src/lib.rs:108`). `open_device` accepts only configurations with `2 <= channels <= want_ch` (`lib.rs:1343`, `1359`); when none matches it falls back to `default_output_config()` (`lib.rs:1376`). On ASIO, cpal lists every width 1..=outs per rate, so a stereo session on the Model 12 matches the 2-channel configuration and opens 2 channels; the default-config fallback bites on WASAPI, where only the mix format is listed (cpal `host/wasapi/device.rs:360-465`, `host/asio/device.rs:97-129`). Either way the other outputs never open. The callback writes main channel k to device channel k and zeroes the rest (`player/audio.rs:603-646`, clamps at 633, 636, 640); a main wider than the device is folded to stereo (`audio.rs:625`, `fold_gains` at `lib.rs:1219`).
- **Hardware routes are input-only, and by string.** `Route` is `None | Main | Bus(BusId) | Hardware(String)` (`model/src/mixer.rs:413`). The mix renders `Route::Hardware` only for monitoring an audio track's input, parsing digits out of a label like "In 1-2" (`mix/src/lib.rs:1824-1828`). `route_into` drops any output that is not `Main` or `Bus` (`lib.rs:1774-1781`); sends to anything but a bus are skipped (`lib.rs:1697`, `1735`). `track.mixer.output = Route::Hardware("Out 3-4")` is accepted from a file and silent. Today's `track.route` command turns an unknown output string into a new bus and maps "out 1-2" to Main (`engine/src/cmd/track.rs:818-838`; UI `ui-studio/src/mixer.rs:410`).
- **`OutputPath` exists; `InputPath` does not.** `OutputPath { name, first_channel, format }` (`model/src/mixer.rs:404`) lives in `Session::outputs` (`model/src/session.rs:317`, no `serde(default)`), seeded with "Out 1-2" (`session.rs:358`). Commands add, edit and remove paths (`engine/src/cmd/setup_more.rs:270-289`). Nothing reads it except `outputs.first().format` as the main format (`mixer.rs:583`, `cmd/surround.rs:105-120`) and the label for `Route::Main` in the UI (`ui-egui/src/mix_window.rs:136`). A 5.1 session stores its format only there.
- **Settings are per machine, but thin.** `AudioConfig { system, output, input, sample_rate, buffer_size }` (`playback/src/devices.rs:27`) lives in `UiState.audio` (`ui-studio/src/lib.rs:54`), saved to `ui.json` in the folder `TRANSIT_CONFIG_DIR` overrides (`apps/transit/src/config.rs`). `DeviceInfo.max_channels` (`devices.rs:44`) is shown but not used to open anything.
- **Input reaches the mix as a flat ring, and recording parses the same label.** The capture stream already opens the configuration with the most channels, uncapped (`playback/src/record.rs:292-306`, `Reverse(c.channels())`); the plan bridge copies it into `input_storage` (`playback/src/plan_bridge.rs:122-165`) and the mix sees `LiveInput.input` (`mix/src/lib.rs:1795`). Monitoring picks `(first + k) % n_in` (`lib.rs:1827-1836`) and recording does the same label parse and wrap (`engine/src/io.rs:1485-1489`, `plan_takes`), so a missing channel wraps silently in both.
- **The route graph, PDC and L22 know three edge kinds.** `EdgeKind` is `Output | Send { slot, pre_fader } | Input` (`model/src/route_graph.rs:36`); hardware and none are not edges (`route_graph.rs:11-12`). Edit-time refusal is `would_create_cycle_all` (`route_graph.rs:667`, from `engine/src/cmd/track.rs:866`); load-time loops are cut by `RouteScratch::solve`, only at the `Input` edge into a component's first track (`route_graph.rs:386-399`), and `dropped` reports only track-to-bus edges (`462-467`); `reserve` sizes edges as sends + 2 per track (`203-206`). PDC is two passes: `pdc_visit` (`mix/src/lib.rs:1643`) records each strip's output latency and each bus's arrival (`main_arrival`, `1659`); `route_into` delays each edge by the summing point's arrival minus the strip's own (`1683-1722`); `path_need_with` (`2594`) sizes the delay lines. Engine latency is `main_arrival + lmax_m` (`1525`) plus master-insert latency (`1498-1507`); delay is clamped at `MAX_LATENCY` (`507`). All of this sees only `Main` and `Bus`.
- **Render order has no track-to-track dependency.** Every non-aux strip runs its whole insert chain in one parallel phase before any routing (`mix/src/lib.rs:1451-1480`, `run_strips` `2486-2501`; plan renderer the same, `mix/src/active.rs:392-405`). `process_strip` gets `&busses` read-only and one `&mut Strip`; the delay lines `tap`/`tap_pre` are written later in `route_into`. `Layering.depth` (`route_graph.rs:100`) orders routing and the aux phase only. "Pre" means after inserts, before the fader (`lib.rs:2013-2018`); `strip.pre` is filled only when a pre-fader send exists (`1975-1981`).
- **Sidechain is not hosted.** VST3 aux buses are inactive (`vst3-host/src/lib.rs:39`); `Plugin::process(&mut self, io: &mut [Vec<f32>], frames)` is one in-place buffer (`dsp/src/lib.rs:223`); the CLAP host binds only the main pair, with bus layout fixed at `activate` (`clap-host/src/plugin.rs:114-130`). The compressor has a sidechain high-pass (`dsp/src/plugins/dynamics.rs:58`) but no key input.
- **Routing changes already travel one safe path.** A control-side compiler builds a `PreparedPlan` (`mix/src/plan.rs:233`) from a `Session` (`mix/src/compile.rs:263`) for a `RenderTarget { device, sample_rate, max_block }` (`plan.rs:55-60`, no channel count). `PlanEnvelope`s go through the bounded publication queue (`playback/src/publication.rs`, `plan_bridge.rs:252-279`); the audio thread adopts at most one per callback at a drained boundary (`active.rs:214`, `Audio::service`, `plan_bridge.rs:524-531`). `DeviceGeneration` means a new device or rate is a new engine (`plan.rs:46-48`). Callback allocation is gated (`mix/tests/plan_alloc_probe.rs`).
- **Offline render is the legacy renderer.** `LegacyPlayer` (`playback/src/lib.rs:641`) is `doc(hidden)` and used only by playback tests; the app's `Player` drives the plan renderer (`MixEngine::render_active`, `active.rs:350`). But `MixEngine::render` (`mix/src/lib.rs:1426`) is the only offline path: `RangeRender::render` (`3480-3485`), `engine/src/io.rs:503-612`, `engine/src/cmd/{mix,instrument,sampler,surround}.rs`, `engine/tests/bounce.rs`, and it is the oracle of `mix/tests/plan_parity.rs`.
- **Discrepancies with the problem statement.** (1) `MAX_CHANNELS` is 16 in the mix (`mix/src/lib.rs:105`) and in `MeterBank`/`Buffers.fold` (`plan_bridge.rs:27`, `125`), 64 in `dsp` and both hosts (`dsp/src/util.rs:14`, `vst3-host/src/gate.rs:12`); 16 binds a path or bus. (2) The output restriction is the `<= want_ch` filter, not a literal "channels 1-2" pick. (3) The path model is per session, not per machine. (4) The `Route::Hardware` label is treated as a channel number, so an input rename silently changes which channel is heard.

Test hardware: TASCAM Model 12 (about 10 outputs and 12 inputs to the host; channel counts may vary with USB mode) and a Focusrite Scarlett 2i2 (2 and 2). Backends: WASAPI and ASIO on Windows, CoreAudio, ALSA, through CPAL in `crates/playback` (pin `derekmwright/cpal`).

## Decision

### 1. Device channel map, with named paths per machine
1. **Open every channel the device offers, up to a cap of 32 outputs and 32 inputs.** The cap is a separate constant, `MAX_DEVICE_CHANNELS = 32`; the 16-channel path/bus width (`MAX_CHANNELS`) is not widened. Meters (`MeterBank.peaks`) and `Buffers.fold` are sized from the `IoMap` (or the 32 cap), not 16. The cap is new only for inputs, which already open at their maximum count uncapped; wider devices open the first 32 and say so in Audio Devices. The output stream is opened at the device's channel count, the `<= want_ch` filter is removed, and selection prefers the highest channel count at the chosen rate and format. **Stated limit:** WASAPI shared mode lists only the system mix-format channel count, so on Windows multichannel means ASIO; Audio Devices says how many channels the current system offers.
2. **A path is a name, a width and a channel set.** `IoPath { name, direction, channels: Vec<u16>, format: ChannelFormat }`, width 1 to `MAX_CHANNELS` (16), `channels` an explicit list so a path may be non-contiguous. `OutputPath` becomes the output half; `InputPath` is added. Defaults when a device opens: "Out 1-2" stereo plus one stereo path per remaining pair, "In 1" mono per input plus stereo pairs. The generated names equal today's labels exactly ("In 1", "In 1-2", "Out 3-4") so existing sessions keep their meaning.
3. **Paths are per machine, and reach the engine as an `IoMap`.** `IoMap { device identity, opened input/output channel counts, named path table, Main's target path }` is loaded by the app from `ui.json` (beside `AudioConfig`; keyed on audio system plus device name, with the channel count stored inside it, so one device in two USB modes is one entry) and handed to the engine with a `setup.io` command. `PlanCompiler::compile`, `Buffers::prepare` and `Player::prepare` take the `IoMap`; `RenderTarget` gains the opened output and input channel counts. Headless and automation (MCP, engine tests) build a default `IoMap` from the device, Main on its first two channels. The path commands (`create_output`, `rename_output`, `delete_output`) edit the `IoMap` the engine holds and the host persists, so they stay scriptable and undoable. **`Session::outputs` stays, in the file, with its current shape, through slices (a) and (b):** it remains the source of `main_format()` and the seed for a first default table, so a 5.1 session never silently becomes stereo (a build that dropped the field would load old files with no error, `mixer.rs:585`). Retiring it needs a versioned migration (`FORMAT_VERSION`, `session.rs:342`; `Session::from_json` has no migration hook today) and its own ADR.
4. **Assignments are per session, by path name.** `Route::Hardware(String)` stays the on-disk variant and means "the I/O path with this name" for inputs and outputs. Names are unique across buses and paths (bus and path share one namespace for `track.route`); `parse_route` resolves path table first, then bus, and creates a bus only on explicit request. On a load collision the bus wins and the route is flagged. Monitoring and recording resolve inputs through one function (`engine/src/io.rs:1485` joins `mix/src/lib.rs:1827`); a missing input path refuses to record with a message and never records a wrong channel.
5. **Resolution when a name is missing on this machine.** An output route to a missing path renders to a **flagged silent sink**: muted, shown in the UI and on load, the session not rewritten. A cue or click mix never lands on the PA. Only the Main path itself falls back to device channels 1-2. A missing input falls back to the first input path of the same width, else silence with a flag. The session keeps the original name, so the right machine restores the routing. Fold or fan-out of widths follows `build_matrix` (`mix/src/lib.rs:3207`). **Bounce is machine-independent:** it renders sinks logically, tracks routed to a named path are excluded from the main bounce, and stems are slice (e).

### 2. Routing matrix
Every track, bus and send may target `Main`, any `Bus`, or any output path; today's default (`Main`) is unchanged. A track's output goes to one target, its sends to as many as it has slots, so main plus cue mixes plus stems are a track output plus sends. The mix keeps one accumulation buffer per device channel (preallocated at the cap) and every path sums into its channel set. Paths overlapping on a device channel sum, with a warning on each ("Out 3-4 shares channel 3 with Headphones"). Metering and clipping apply per device channel after the sum, with the existing clamps (`audio.rs:633, 636, 640`). The device-frame layout travels with `Buffers` (as `fold` does), so render-ahead blocks keep their old layout across a path edit. There is no full matrix-mixer UI (see Alternatives).

### 3. Main as one path among paths
The main mix remains the primary output and still sets the main format (`Session::main_format`, `mixer.rs:583`). Which path Main plays on is stored per machine in the `IoMap` (default "Out 1-2"), which also answers what `Route::Main` shows in the UI (`mix_window.rs:136`).

### 4. Sidechain key inputs are edges in the route graph
An insert gets an optional key: `Insert.key: Option<KeySource>` with `#[serde(default, skip_serializing_if = "Option::is_none")]` like its sibling fields (`mixer.rs:428-443`), so old sessions load. `KeySource { from: KeyFrom, tap: Pre | Post }`, `KeyFrom { Track(TrackId), Bus(BusId), Send { track, slot } }` (`Route` cannot name a track). The key belongs to the slot and moves with it on reorder, copy and presets. `EdgeKind` gains `Key { slot, pre_fader }`.

**Execution rule (dependency layering).** A strip whose insert has a key from another strip renders in a later layer than its key source: `Layering` extends from routing edges to key edges, and phase 1 runs as one `run_strips` call per layer. `process_strip` gains a read-only key view (the source strip's tap or pre buffer, written when its layer finishes), a borrow change that is safe because layers are disjoint. Kick-to-bass must work. A bus key reaches only a strip rendered after the bus fills (an aux). A key cycle is refused by L22 like any loop. If layering proves too costly in slice (c), the fallback is a one-block-delayed key with the delay counted in PDC; "aux-only keys" is rejected as a product limit.

**Loops and sizing.** The load-time cut in `RouteScratch::solve` assumed every loop holds an `Input` edge; a two-track mutual key holds none. The cut rule, `dropped` and `reserve` (count insert slots) change, with a test loading a two-track mutual key from a file; edit-time refusal gains `RouteChange::Key`.

**Delivery and alignment.** The mix writes the key tap into a preallocated per-strip key buffer and passes it through `Plugin::process_with_key(&mut self, io, key: &[Vec<f32>], frames)`, default ignoring the key. Alignment point: the keyed slot's input (inserts before it may be latent, `process_strip` accumulates latency per insert, `lib.rs:1928-1947`). A late key (key latency above the keyed signal's) delays the keyed strip's input through a per-strip pre-slot delay line sized at compile and counted in `strip.latency` and PDC; an early key delays only the key. A Pre tap counts as a consumer for `strip.pre`, `tap_pre` and `path_need_with`. Channel mapping uses `build_matrix` (mono kick into a stereo aux bus).

**Hosts.** The VST3 host activates the aux bus and the CLAP host the sidechain port at instance creation whenever the plug-in declares one, and feeds silence (silence flag) when unrouted, so key edits are ordinary plan changes and never touch a live instance. `run_insert`'s suspend logic (`lib.rs:2081-2113`) considers the key as well as the main input, so a silent main with a loud key does not sleep a ducker. Built-in compressor and gate read the key in place of their own input when set. Implementation is slice (c).

### 5. Hardware inserts
A hardware insert is a send to an output path plus a return from an input path: a sibling `Option<HardwareInsert { send, ret }>` on `Insert` (`Insert` is a struct, `mixer.rs:425`), by path name. **Duplex only:** it needs input and output on one clock, which is ASIO on Windows (`player/device.rs:200-232`); on other backends the drift invalidates a fixed measured latency, so the insert is unavailable and flagged. The return for block N arrives in a later callback: the slot is a send, a FIFO of the measured round-trip length, and a read from the input ring, and `latency()` equals that length (the measured value covers the blocks of delay). A ping measurement writes an impulse on the send path, finds it on the return and stores `{ send, return, device identity, rate, buffer, frames }` per machine. No measurement means zero latency and a flag. A missing path bypasses the insert dry, flagged. Offline render is dry bypass with a flag. Implementation is slice (d).

### 6. PDC and L22 across all edge kinds
Every sink (Main, each output path, each hardware send) is padded to one shared device latency L = max over all sinks of their arrival, plus the master-insert latency (`main_arrival + lmax_m`, generalized). A path fed only by a zero-latency track is delayed to L, so stems and cues align with Main sample for sample. `path_need_with` sizes per-sink capacity and respects the `MAX_LATENCY` clamp (`lib.rs:507`). One stated exception: a path declared "live" (a performer's headphone cue) may opt out of compensation, off by default. Sidechain edges align at the keyed slot input (section 4); hardware insert latency counts through `latency()`. `route_graph`, `pdc_visit`, `route_into`, `path_need_with` and `RouteScratch` change together per slice. New `plan_parity` cases for sinks and keys compare against hand-computed golden outputs, not the legacy renderer. Outputs to paths are not loopable edges (sinks have no readers); only key edges add cycles.

### 7. Realtime and publication
Path tables, key sources and the channel map reach the audio thread inside `PreparedPlan` through the bounded queue and the single adoption per callback. Accumulation buffers, key buffers, pre-slot delay lines and sink scratch are allocated by the compiler from the `RenderTarget` and `IoMap` and move with the existing cell moves; `RouteScratch::reserve` grows. **Only a device or opened-channel-count change is a reopen** (`DeviceGeneration` bump). Path and route edits are structural plan changes adopted at a drained boundary, never a stream stop, and must not swap a still-audible output buffer (`Audio::service`). `plan_alloc_probe` gains each new route kind. No `unsafe` is added (ADR 0013).

## Implementation plan: slices, crates, gates

Each slice ships alone, gets a refutation review (ADR 0009), and leaves stereo behavior unchanged.

**(0) Offline render onto the plan renderer.** Move `RangeRender`, `render_range`, `render_bus` and `engine/src/io.rs` export/bounce onto `PlanCompiler::compile`, `adopt_plan`, `render_active` with an offline target; convert the `plan_parity` oracle tests to golden outputs; then delete `LegacyPlayer` and `MixEngine::render`. New sinks, key edges and hardware inserts are built only on the plan renderer. Gate: `plan_parity` goldens and `engine/tests/bounce.rs` pass bit-identical.

**(a) Open all device outputs; Audio Devices shows them; paths editable.**
Files: `playback` (`lib.rs` `open_device`, `devices.rs` identity, `player/audio.rs`, `player/device.rs` `Player::prepare`, `plan_bridge.rs` `Buffers`, `MeterBank`, `fold`), `mix` (`plan.rs` `RenderTarget`, `compile.rs`), `model` (`IoPath`), `engine` (`setup.io`, `cmd/setup_more.rs`, `cmd/track.rs` `parse_route`, `io.rs` shared input resolution), `ui-studio` (`audio_devices.rs`), `apps/transit` (`config.rs`).
Gate: a fake device opens 10 and 2 channels, cap holds at 32; the `IoMap` round-trips through `ui.json`; a session with "Out 3-4" on the 2-channel fake shows the silent flagged sink with unchanged session text; a golden 5.1 session round-trip (load, save, compare) keeps `main_format()`; stereo audio bit-identical; bus/path collision and missing input path refuse as stated. Note-level real-hardware gate on the Model 12: same ASIO buffer size, round trip and overrun count with 2 channels open versus 10 out / 12 in (cpal's ASIO streams share one buffer set, `player/device.rs:239-244`), and the Scarlett 2i2 unchanged.

**(b) Route tracks, buses and sends to any output path, with consistent PDC.**
Files: `mix` (`route_into`, `process_strip`, send filters at `lib.rs:1735` and `pdc_visit` `1663-1666`, `path_need_with` `2615-2625`, accumulation buffers, `compile.rs`, `plan.rs`), `model` (`route_graph.rs` sinks, `RouteGraph::load` send filter `263-268`), `engine` (`cmd/track.rs`, `cmd/mix.rs:463` send creation targets paths), `ui-studio` (`mixer.rs`), `playback` (`plan_bridge.rs`). Sends now target output paths, so cue mixes work.
Gate: two different tracks with different plug-in latencies routed to two different sinks (Main and a path) land sample-aligned after removing L; overlapping paths sum; a missing path is a silent flagged sink; `plan_alloc_probe` shows zero callback allocations across path edits; golden `plan_parity` cases.

**(c) Sidechain key routes and host wiring.**
Files: `model` (`Insert.key`, `KeyFrom`, `EdgeKind::Key`, `RouteChange::Key`, `route_graph.rs` cut and `reserve`), `mix` (dependency layers, key buffers, pre-slot delay, PDC), `dsp` (`process_with_key`, compressor and gate), `vst3-host`, `clap-host`, `engine`, `ui-studio`.
Gate: key loop refused at edit and cut at load, including a two-track mutual key; kick-to-bass key in the parallel renderer and again with `serial` forced, identical output; late and early keys aligned within one sample with a latent earlier insert; a Pre tap; fixture VST3 and CLAP plug-ins receive the key; a compressor ducked by a kick matches a hand-computed curve; no key leaves the plug-in on its own input unchanged; a silent main with a loud key does not suspend the insert.

**(d) Hardware inserts with latency measurement.**
Files: `model`, `mix` (send/return slot, `latency()`), `playback` (loopback ping, duplex only), `ui-studio`, `apps/transit`.
Gate: a fake-duplex loopback with a known delay measures it to the frame and PDC aligns a parallel dry track; a long-run stability test in the fake; unmeasured flags and counts zero; missing return bypasses dry; offline is dry bypass; Model 12 out 3-4 to in 3-4 loopback recorded as a note.

**(e) Stems.** Bounce over output paths on the plan renderer (needs slice 0). Gate: a stem render per path sums to the main bounce for non-overlapping paths.

## Consequences

- A session built on the TASCAM opens on the Scarlett with path-targeted outputs silent and flagged; nothing is lost, nothing is rewritten, and no cue reaches the PA.
- `route_graph.rs`, `pdc_visit`, `route_into`, `path_need_with` and the compiler change together per slice. Slice 0 removes the second renderer first so each change is made once.
- `Plugin` gains a defaulted method, touching `dsp`, `vst3-host`, `clap-host`; upstream offers need care, as with ADR 0012's note API.
- The settings schema grows (`ui.json` `IoMap` tables, measured latencies); old files load with defaults. The session file is unchanged through (a) and (b), so older builds still read it.
- Stereo-only users pay nothing: one stereo path, identical output. The 32-channel cap is a documented limit raised by one constant and the scratch budget. On Windows, multichannel requires ASIO.

## Alternatives considered

- **Keep two-channel main plus per-track direct outs.** Smallest change. Rejected: a parallel mechanism beside buses and sends, no cue mix summed from several tracks, no home for sidechain or hardware inserts.
- **A full matrix-mixer UI like RME TotalMix.** Rejected for now: asks users to re-solve routing a session already states, duplicates a mixer, and sums at the device without PDC awareness. Revisit if direct-monitor routing for devices without a hardware mixer becomes a goal.
- **Per-session device channel numbers, no named paths.** Rejected: breaks on any other interface and cannot show a human name. Names resolve per machine; numbers do not.
- **Paths stored in the session (today's `Session::outputs`).** Rejected for paths: the session would carry device facts. It stays only as the main-format source (section 1.3).
- **Cap at the main width, or at 16.** Rejected: 16 is the width of a path, not of a device.
- **Sidechain as a special per-plug-in parameter, or aux-only keys.** Rejected: the first hides a dependency from loop refusal and PDC; the second makes kick-to-bass impossible, the common case.
