# ADR 0016: Native WASAPI backend behind a platform-independent audio backend trait

- **Status:** accepted 2026-10-21 (direction from the project owner; refutation review round 1 resolved); implementation after ADR 0015 slice (c)
- **Date:** 2026-10-21
- **Implementation:** slice (a) landed 0ef51ae. None yet for the rest. Slices (a) to (f) below, each shippable, sequenced after ADR 0015 slice (c). Slice (c) improves output latency and the render clock, which helps live MIDI monitoring; slice (d) adds capture and calibrated placement for recording. Both touch the MIDI clock path.
- **Reopen when:** the benchmark harness (slice b) shows CPAL-shared already within the gate margin of ASIO on both reference interfaces (measured by the method in section 5, so this cannot fire before slice b); or the native shared low-latency path cannot beat CPAL-shared on the Scarlett 2i2 and the TASCAM Model 12 after slice (c); or `IAudioClock2` device positions prove no better a clock than QPC arrival on the reference drivers (slice d gate fails); or upstream CPAL gains exclusive mode, `IAudioClient3` and device-position timestamps.

## Context

The project owner asked for a native WASAPI backend, because CPAL's is shared-mode only and its clock is the root of the clock-fit trouble. Verified against `soundcraft` branch `transit`, head 6f89d2b (paths relative to `crates/`):

- **The Player calls cpal directly, in several places.** `Player::open` picks a device, builds an output stream per sample format and starts it (`playback/src/player/device.rs:208-283`; the per-format `build_output::<T>` fan-out at `234-246`, the stream builder at `747-780`). `open_device` resolves the host and device, then `choose_output` (`lib.rs:1348`) picks a configuration from `supported_output_configs()`, else falls back to `default_output_config()` (`lib.rs:1395-1425`). `output_attempts` retries narrower or with the default buffer (`lib.rs:1378`). The recorder builds its own input stream (`record.rs:294-326`, `build_input` `230-262`). Other cpal leaks the trait must absorb or retire: `LegacyPlayer` (`lib.rs:641` to about 850, with its own `build_output`; slated for deletion in ADR 0015 slice 0 part 2), `OutputCallback` and `output_error_callback` (`lib.rs:1248-1291`, `cpal::SizedSample`, `StreamError`), `scheduling.rs:30-50` (`stream.as_inner()` and `StreamInner::Wasapi` thread-priority observation, a fork-only API), the `ASIO_OUTPUT: Mutex<Option<cpal::Device>>` static (`devices.rs:185`), test code that builds `cpal::SupportedStreamConfigRange` (`lib.rs:1446-1470`, 2687), and the wasm32 and FreeBSD cfgs.
- **WASAPI is shared-mode and mix-format only through CPAL.** The `WASAPI` host is whitelisted as physical channel order (`lib.rs:1337-1339`), but the only configuration it lists is the system mix format. ADR 0015 already records that on Windows more channels means ASIO. There is no exclusive mode, no `IAudioClient3` small-period stream and no raw mode in the pin. ASIO is an optional feature that downloads Steinberg's SDK (`playback/Cargo.toml:41`).
- **Duplex is ASIO-only today.** `input_with_output` returns true only for ASIO (`lib.rs:147-149`) because cpal's ASIO driver is one per process. On WASAPI the input is a second, independent stream on its own clock. ASIO duplex has a hard build order: input first on the output's own `cpal::Device`, started separately (`device.rs:217-224`, `lib.rs:781-796`); adding a direction later can hang. ADR 0015 section 5 therefore limits hardware inserts to ASIO.
- **The clock service takes a `cpal::StreamInstant` pair.** `CpalObserver::{input, output}` turn the `callback` and `capture`/`playback` instants into a `Stamp { host_callback_ns, backend_callback_ns, backend_frame_ns, quality, offset_uncertainty_ns }` (`playback/src/device_clock.rs:466-525`, `Stamp` at `43-52`), as signed `i64` offsets from a first-callback origin (`relative_ns`, `472`; negative values are legal). The best quality the pin can claim is `BackendEstimate` (`516-519`); `Quality::Measured` exists (`35-40`) and nothing produces it. Output and input each get their own `ClockKey` domain (`582-593`, `domain: generation`). The ADR 0012 annex records why: CPAL's WASAPI output time is QPC plus `frames_available / rate` with the device position discarded, capture uses the first-frame QPC with its quality flags dropped, and the live probe saw capture anchor failures and no convergence on a second output open ([the clock annex](0012-clock-contract-annex.md); coordinates: host time H, backend time B, device frames D).
- **The audio callback is already backend-neutral past the buffer.** `fill_inner` (`player/audio.rs:595-650`) fills an `f32` interleaved slice using the `Buffers` layout (`plan_bridge.rs:120-135`); device-format conversion is `OutputCallback::fill`. The clock hook is one line (`clock.cpal.output(frames, info, now)`, `device.rs:769`). `IoMap` (`model/src/io_map.rs:64-72`) carries no cpal type.
- **The cpal pin is a fork with three patches** (`Cargo.toml:90-92`, `derekmwright/cpal` at `31b5dd4`): the WASAPI lifetime fix (upstream PR #1406, closed as over-engineered), worker-priority observation, and signed timestamp arithmetic. Per the standing upstream rule a Windows backend redesign is not an upstream contribution.
- **`unsafe` has one home** (ADR 0013): `soundcraft-rt`, which already calls `AvSetMmThreadCharacteristicsW` through `windows-sys` (`rt/src/windows.rs:53`). Its promotion keeps a `thread_local` saved state (`windows.rs:33`), so it must be called and reverted on the thread that runs the loop. COM needs the `windows` crate; `Cargo.lock` already holds 0.54, 0.56 and 0.62.2.
- **Context:** transit decides for transit (ADR 0013 amendment, 2026-10-21). The unsafe rules (quoted SAFETY, refutation review, safe fallbacks, platform independence) stay.
- **Hardware.** Focusrite Scarlett 2i2 (2 in, 2 out), TASCAM Model 12 (about 12 in, 10 out), both with ASIO and WASAPI drivers; the ASIO build is the best-known baseline.

## Decision

### 1. A backend trait, new crates, cpal kept
1. **`crates/audio-backend`** (`soundcraft-audio-backend`, `unsafe`-free, no cpal, no `windows`) defines the trait. **`crates/audio-wasapi`** (`soundcraft-audio-wasapi`, Windows only) implements it. Both are registered in xtask `LAYERS` (`xtask/src/main.rs:20`, which fails an unregistered crate). The cpal adapter lives in `playback` (`backend/cpal.rs`) and is the only user of cpal types after slice (a); `ClockReader`, `Buffers` and `IoMap` stay.
2. **The trait.** `Backend::endpoints(direction)` returns id, name, container id, mix format and min/default period frames only (no format enumeration; see section 2). `Backend::open(OpenRequest { endpoint, direction, format, period_frames, mode })` returns `Result<(Stream, Achieved), OpenError>`, where `Achieved` is the actual rate, channels, period, format and first-frame ordinal (what `Player::open` needs for `device_channels`, `device_buffer`, `IoMap::for_device`, and the input's `clock.cpal.next_frame()` at `record.rs:241`). `OpenError` distinguishes `DeviceNotAvailable` from other errors (the Fault path at `device.rs:806` and `lib.rs:1291` branches on it). `Stream::{start, stop, latency}`. There are two callback types, render `FnMut(RenderBlock)` with `&mut [f32]` and capture `FnMut(CaptureBlock)` with `&[f32]`. Both carry `frames`, `backend_callback_ns: i64`, `backend_frame_ns: i64` (signed, origin-relative, exactly what `CpalObserver` produces, so the cpal adapter does its own `relative_ns` and the native backend fills the same fields) and `BlockQuality` (discontinuity, timestamp error, glitch). `Backend::on_device_change(handler)` reports unplug and default-device change. There is no `open_duplex`: the Player opens render and capture as two opens, and the cpal adapter owns the ASIO ordering (input built first, started separately, `HeldInput` and `Recorder::start` lifetimes unchanged). The sample-format fan-out (`device.rs:234-246`) moves into the adapters, so the Player sees `f32` blocks.
3. **Selection.** The Windows default is cpal until slice (f). A per-machine `AudioConfig.backend` (`Auto | Cpal | NativeWasapi`, saved in `ui.json` beside `AudioConfig`, `devices.rs:27`) and a `native-wasapi` Cargo feature select it. Every `OpenError` from the native backend falls back to the cpal adapter for that open, logs once, and says "Native WASAPI failed: <reason>; using the cpal backend" on the status line and in Audio Devices (slice c part 2). The Backend selector (Auto / cpal / Native WASAPI (experimental)) appears in Audio Devices only in a build with the feature, on the WASAPI system; the load readout shows `WASAPI*` while the native backend serves the device. The fallback happens **before `start()` only**: a fault after the stream runs takes the existing Fault path, never a silent re-open (that would create a new clock generation under a running transport). Linux and macOS have only the cpal adapter.

### 2. Modes: shared low-latency by default
- **Shared mode through `IAudioClient3`** (`GetSharedModeEnginePeriod`, `InitializeSharedAudioStream`, event-driven) is the default. It coexists with other apps and reaches small periods (about 2.7 ms at 48 kHz, 128 frames) only where the driver publishes a small minimum; that is a driver property and the Focusrite and TASCAM drivers may publish only 10 ms. The app shows the real floor and, where it is the 10 ms default, says so and offers exclusive. Slice (b) records `GetSharedModeEnginePeriod` for both interfaces; if min equals default on either, the (c) value case for that device is nil and this ADR is amended to say what ships.
- **Shared format policy.** Shared mode uses the endpoint's configured Default Format (what the user set in the Sound control panel), which fixes channel count and rate; multichannel works only if that default has more channels. The backend requests the endpoint's mix rate, never sets `AUTOCONVERTPCM` or `SRC_DEFAULT_QUALITY`, reports `device_rate`, and the Player resamples as today (`lib.rs:1403-1405`). A Default Format change while running arrives as `DisconnectReasonFormatChanged`, invalidates the client and is handled as in section 4.
- **No format enumeration.** WASAPI has none. `endpoints()` returns only the mix format and periods (cheap, safe during UI enumeration). Shared mode advertises the mix rate alone: `IsFormatSupported` answers `S_FALSE` for any other rate, so it cannot discover the rates `AUTOCONVERTPCM` converts, and the open path asks for the session rate instead. Exclusive formats come from an explicit `probe_exclusive(endpoint, candidates)` over a bounded candidate list (`STANDARD_RATES`, channel counts, 32-bit, 24-in-32, packed 24, 16-bit) using `IsFormatSupported`, called from the open path and the device-report screen only, because probing a device another app holds fails and can be slow. `choose_output` becomes a backend-neutral selection over the open-path probe results; the existing `choose_output` and `output_attempts` tests are rewritten over a neutral type and the cpal adapter's conversion gets its own tests (they cannot pass "unmodified" over both).
- **Exclusive mode** (slice e) is opt-in per device ("Exclusive: lowest latency, other apps are silenced"), event-driven, any probed format including multichannel. Rules: `hnsPeriodicity` must equal `hnsBufferDuration`; on `AUDCLNT_E_BUFFER_SIZE_NOT_ALIGNED` the `IAudioClient` is re-activated (a failed `Initialize` cannot be retried on the same client), `GetBufferSize` gives the aligned frame count and the duration is recomputed; the `WAVEFORMATEXTENSIBLE` carries `wValidBitsPerSample` and subformat for 24-in-32 and packed 24 (`devices::FORMATS` has only f32/i32/i16 and grows to cover them); "exclusive disallowed" in the endpoint's Advanced settings is a distinct `OpenError`; a device held by another app is a normal `OpenError`.
- **Raw mode** (slice c, where APOs sit in the path) uses `IAudioClient2::SetClientProperties` (`Options = RAW`) before `Initialize`, when `PKEY_Devices_AudioDevice_RawProcessingSupported` reads true; failure degrades to non-raw with a flag in the device report. It is moot in exclusive mode.
- **Channels.** ADR 0015's width rule, `MAX_DEVICE_CHANNELS` cap and unchanged-stereo behavior apply. Channel order comes from the channel mask: physical order holds for mask 0 (`KSAUDIO_SPEAKER_DIRECTOUT`, channel i is device channel i, usual on pro interfaces) and stereo; for other masks (5.1/7.1) the mask order is not physical order, so open falls back to stereo or the app maps by index and warns. `physical_channel_order` is set only for those cases.

### 3. Clocking: replace the CPAL stamp, keep the fit
- **Render and capture are two clients on two endpoints** (separate `IMMDevice`s, `IAudioClient`s, event handles, threads and position counters). The only shared timeline is QPC. There is no common frame counter and no "render master".
- **Each stream has its own `ClockKey` domain**, fed from its own `IAudioClock2` position plus QPC. "One clock" for duplex means both domains are fit against the same host origin (QPC) and a validated rate ratio between them per the ADR 0012 annex (equal nominal rates do not prove equal clock rates); the ratio, its bound and its span are stated in the fixture, which covers a ratio-1 case and a drifting-pair counter-case. Nothing in `ClockFitter` changes: sharing a domain tag does not make capture use the render fit, so none is shared.
- **Pairing rule.** A render and a capture endpoint pair when they have the same `IMMDevice` container id (`PKEY_Device_ContainerId`, the physical interface); otherwise the user pairs them in Audio Devices.
- **Hand-off.** `IAudioClock2::GetDevicePosition` returns the device position in frames and a QPC timestamp in **100 ns units** (so does `IAudioCaptureClient::GetBuffer`). At stream start the backend captures one `(QPC, Instant)` pair and converts every stamp to the Player's `HostOrigin` (a `std::time::Instant`) through it, as signed origin-relative nanoseconds like `CpalObserver`'s. `playback` stays `unsafe`-free and never calls QPC; the backend supplies the pair. Render block presentation time is `qpc(D) + (GetCurrentPadding + GetStreamLatency) / rate`: the position at callback entry is the frame now being played, so the first frame written is presented one padding plus one stream latency later. Capture's `backend_frame_ns` is the packet QPC.
- **Callback HRESULTs are allocation-free.** On the audio thread every `HRESULT` is translated to a small `Copy` enum from the raw code; `windows::core::Error` is never constructed or formatted there (it captures `IErrorInfo` and can allocate). Device position can be coarse (per DMA or USB packet) and is a COM call, so slice (c) measures its per-call cost before it is used in the callback, with `Arrival` quality as the fallback if it is unbounded.
- **Observer and quality.** `device_clock.rs` takes the signed `Block` stamps; `CpalObserver` remains the cpal adapter's mapping and `NativeObserver` is the native one, both producing the same `Stamp`. No position or `TIMESTAMP_ERROR` is `Invalid`; a position without a calibrated offset is `BackendEstimate`; a discontinuity bumps the clock generation. **`Measured` is awarded only after slice (d)'s loopback calibration** and inherits the existing rule that it cannot exist without an uncertainty bound (`device_clock/tests.rs:419`). ASIO stays on the cpal adapter and its own observer, unchanged, at `BackendEstimate` or `Arrival`; its `Measured` path needs asio-sys position and latency calls and is out of scope.
- **Calibration defined (slice d).** The user runs an in-app loopback wizard (output to input cable). The offset is stored per device, mode, rate and period, and reset to `BackendEstimate` on any change of those. The measured round trip already contains output latency, input latency and converter delay, so `GetStreamLatency` is not added on top of it (no double counting); it is used only for the uncalibrated estimate. `offset_uncertainty_ns` is the spread of N clicks plus the device-position granularity. "Calibrated" in the UI means `Quality::Measured` with its uncertainty shown, and nothing else.
- **Annex gates.** G4 (observation seam, bounded fit, hardware placement): a hardware run records `Observation`s from the native backend with a fit residual below `MAX_RESIDUAL_NS` (2 ms, `device_clock.rs:16`) at 64, 128 and 256 frames and 44.1, 48 and 96 kHz (annex matrix; at 64 frames the period is 1.33 ms, so the bar is tight and the spread is reported), stored with the benchmark results; the placement test of slice (d) puts a loopback-recorded click within one frame of its prediction. G9 (no callback allocation) holds through the checks in section 4. G6 (the runtime-owner decision) and G8 are not touched. The real G4 tests are `device_clock/tests.rs` and `tests/publication_contract.rs`; `playback/tests/backend_time_contract.rs` tests only cpal-fork `StreamInstant` arithmetic and gates nothing here.

### 4. Unsafe, threading, lifecycle
- **ADR 0013 amendment** (dated, recorded in ADR 0013): `unsafe` may also live in `soundcraft-audio-wasapi`, for COM and Win32 calls only. `playback`, `mix`, `engine`, `model` and `audio-backend` keep `#![forbid(unsafe_code)]`. `cargo xtask layers` gains an `unsafe` allowlist check (ADR 0013 decision 8) so the placement is enforced. `audio-wasapi` is wholly under `#![cfg(windows)]` with `windows` (0.62, shared with accesskit) under `[target.'cfg(windows)'.dependencies]`, so it compiles to an empty crate on Linux and macOS, where CI runs `cargo clippy --workspace` and `cargo test --workspace`.
- **Bindings** are the `windows` crate. Each `unsafe` block has a `// SAFETY:` comment quoting the COM or WASAPI rule, for example "`GetBuffer` must be paired with `ReleaseBuffer` with the same frame count before the next `GetBuffer`".
- **Threading.** winit initializes OLE (STA) on the UI thread; `CoInitializeEx(MTA)` there would fail with `RPC_E_CHANGED_MODE`, so no WASAPI object is created on it. Each stream is owned by one dedicated thread that calls `CoInitializeEx(COINIT_MULTITHREADED)` and creates and uses every COM object (`IMMDevice`, `IAudioClient`, clocks, capture and render clients), plus the event handle and the MMCSS registration, and runs the callback loop. Control talks to it only through lock-free commands and the existing publication path. **Rule: no COM interface pointer crosses threads without marshaling**, so no `unsafe impl Send` for COM types. `IMMNotificationClient` callbacks arrive on COM's own threads and only post events (an atomic or a bounded channel); unregister happens before release and never from inside a handler. On panic the thread unwinds, releases everything, calls `CoUninitialize`, and the Player falls back to cpal with a visible message. Render and capture are two threads with two `soundcraft-rt` promotions, each reverted on its own thread. A test opens a stream from an STA thread.
- **Quoted-unsafe refutation review** (ADR 0009 plus ADR 0013 decision 6): a fresh-context reviewer gets the unsafe blocks and the Microsoft excerpts they cite and tries to refute each SAFETY claim; the verdict is recorded before a slice's gate counts as met. A COM `#[implement]` notification client needs its whole type (reference counting, vtable layout), not blocks in isolation. A later defect adds a gate class, not a patch.
- **Safe fallbacks.** Nothing panics. Every `HRESULT` becomes an `OpenError` or `StreamError`; a callback that cannot read the clock publishes `Invalid` and keeps rendering. Logic is tested off Windows behind a `ComApi` trait inside `audio-wasapi` (the ten or so calls used); a Windows-only suite exercises the real calls and skips when no endpoint exists.
- **Callback discipline.** No locks, no allocation; handles, buffers and COM objects exist before `Start`; render is pre-filled with silence before `Start`; capture loops `GetNextPacketSize` (several packets per event) and always pairs `GetBuffer` with `ReleaseBuffer`; the loop waits on the buffer event and a stop event with `WaitForMultipleObjects` and a timeout, so a stalled or unplugged device cannot block `Stop`; `AUDCLNT_E_DEVICE_INVALIDATED` and `AUDCLNT_E_RESOURCES_INVALIDATED` map to `DeviceNotAvailable`; `IAudioSessionEvents` covers format change and disconnect; with `cfg.output` `None` a changed Windows default raises a Fault with a message (no silent re-open); sleep and resume invalidate and take the same path.
- **Allocation gates.** Because the fake COM layer cannot see allocations inside real calls, (1) a `measure`-style zero-allocation test drives the callback over a real stream behind an `#[ignore]` hardware gate, and (2) clippy bans `to_string` and `format!` (and `windows::core::Error` construction) in the callback module.

### 5. Benchmark harness first (the project owner's requirement)
`cargo xtask audio-bench` drives the trait, so cpal-shared, cpal-ASIO and native are measured by identical code, and by host time only:
- **Callback jitter and achieved period:** host-arrival QPC at callback entry; p50, p99, max against the achieved period, reported in ms.
- **Round trip:** a loopback cable; the output callback stamps host QPC plus the click's frame offset, the input callback stamps host QPC of the detected click. Works for any backend that can open input and output, even as separate streams (cpal-shared). State the bias (callback dispatch jitter, annex) and report the spread. A device-position round trip is an additional native-only column.
- **Xruns:** native from discontinuity flags and underrun detection; cpal from the Player's own missed-deadline telemetry (`fault.beats`) and a gap in arrival times; marked "not observable" where none exists. Two minutes, then with a 70 percent CPU load thread.
- **Matrix:** 32, 64 and 128 frame requests at 48 kHz on the Scarlett 2i2 and the Model 12 (loopback on one out/in pair), CPAL-shared and ASIO as baselines. Each backend is compared at its own achieved period, never a common buffer size; if CPAL-shared cannot open below period P, the gate is evaluated at P and at the native minimum, and the table shows both.
- **Output:** markdown table and raw CSV in `docs/benchmarks/<date>-<machine>.md` with interface, driver, Windows build and achieved period. A fake-device mode (software loopback with a known delay) runs inside the existing tag-only `cargo xtask ci`; no new workflow or trigger. Hardware numbers are notes, never CI gates; hardware tests skip with no endpoint.
- **Gate.** The native backend achieves a smaller period than CPAL-shared and a round trip within a margin of ASIO, both measured by the same host-QPC method, the margin fixed by amendment after the slice (b) baseline (starting value 1.5 ms at 64 frames). Jitter p99 is gated; xrun counts are reported and gated only where the baseline reports them.

## Implementation plan: slices, crates, gates

Each slice ships alone, gets a refutation review (ADR 0009), and leaves behavior unchanged until its gate says otherwise.

**(a) The backend trait and the cpal adapter (no behavior change).**
Files: new `audio-backend`; `playback` (`lib.rs` `open_device`, `choose_output`, `output_attempts`, `OutputCallback`; `player/device.rs`; `record.rs`; `scheduling.rs` thread-priority observation behind a trait method or the adapter; `devices.rs` `ASIO_OUTPUT`; wasm32 and FreeBSD cfgs; `LegacyPlayer` is retired first via ADR 0015 slice 0 part 2, or included); `device_clock.rs` takes signed stamps; xtask `LAYERS`.
Gate: `plan_parity` never reaches device code, so before the refactor record goldens of `OutputCallback::fill` bytes for f32, i32, i16 (and the 8/24-bit formats cpal lists) over a fixed render, of the recorder's f32 capture over fixed input bytes, and of the `Stamp` sequence `CpalObserver` produces for fixed `StreamInstant` inputs; the adapter reproduces all three bit for bit. A fake `Backend` (scripted blocks) drives `Player` end to end in a hermetic test. Cpal types appear only in the adapter and `devices.rs`. An ASIO open, duplex, close and reopen on the Scarlett is a required hardware check, as is WASAPI opening unchanged.

**(b) The harness and the baseline table.**
Files: `xtask` (`audio-bench`), `docs/benchmarks/`.
Gate: the fake loopback recovers its known delay to the frame; CPAL-shared and ASIO tables for both interfaces committed, with `GetSharedModeEnginePeriod` recorded; the margins fixed by amendment.

**(c) Native WASAPI render, shared low-latency, raw where supported, behind a feature and toggle.**
Files: new `audio-wasapi` (endpoints, `IAudioClient3`, render client, event and stop handles, `rt` promotion on the stream thread, `IAudioClock2`, session events, default-device follow); `playback` (selection); `ui-studio` `audio_devices.rs`.
Value, stated honestly: lower monitor and playback output latency and a render clock with `BackendEstimate`. Recording still uses cpal's input; MIDI timing improves for live play here and for recording in (d).
Gate: the section 5 gate on both interfaces; fallback to cpal on every injected open failure; hot-unplug, device invalidation, format change and default-device change reach the Fault path; zero callback allocations (both checks); a stream opened from an STA thread works; a cpal input beside a native output still records and places correctly; `audio-wasapi` compiles empty on Linux and macOS; the quoted-unsafe verdict recorded.

**(d) Capture, paired endpoints and calibration.**
Files: `audio-wasapi` (capture client, discontinuity flags, container-id pairing); `playback` (`record.rs` through the trait, `NativeObserver`); `ui-studio` (loopback wizard).
Gate: the clock fit reaches `Measured` and the UI says "calibrated" with its uncertainty; the placement test lands within one frame; a second open converges (the annex's live-probe failure); the paired-domain fixture and its drifting-pair counter-case pass; an ADR 0015 hardware insert measures on WASAPI.

**(e) Exclusive mode; multichannel on the Model 12.**
Files: `audio-wasapi` (`probe_exclusive`, alignment re-activation, valid-bits formats); `playback` `choose_output`; `ui-studio`.
Gate: the Model 12 opens its full channel count in exclusive mode with the same callback overrun count as two channels (the ADR 0015 note-level gate); exclusive-busy, disallowed and revoked-after-open degrade to a message.

**(f) Native becomes the Windows default; cpal fallback stays.**
Gate: a week of the project owner's daily use on both interfaces without a fallback event or harness regression; the release's harness table committed; a documented one-line switch back (`AudioConfig.backend = Cpal`). ASIO stays an option and the baseline.

## Consequences

- One more `unsafe`-bearing crate and a `windows` dependency; the review burden is bounded by the quoted-unsafe pass and by the crate being small and Windows-only.
- The Player loses its direct cpal dependency; the adapter becomes a seam that also helps a future JACK or PipeWire backend.
- Calibrated MIDI timing becomes possible on Windows; until slice (d) the UI keeps saying "approximate".
- ASIO is no longer the only route to low latency or multichannel on Windows, but it remains the baseline.
- Exclusive mode silences other apps by design; the UI must say so at the choice.

## Alternatives considered

- **Keep patching CPAL upstream.** Rejected: slow, shared-only by design, and the minimal-diff rule forbids the redesign this needs.
- **The `wasapi-rs` crate.** Rejected as the foundation: its `unsafe` and COM lifetime handling would sit outside the quoted-unsafe review, and `IAudioClient3` and device-position access are thin. It stays a reference for reviewers.
- **ASIO only on Windows.** Rejected: needs Steinberg's SDK and agreement (pending), one driver per process, no coexistence, nothing for interfaces without ASIO.
- **Exclusive mode as the default.** Rejected: it silences every other app and fails when the device is busy; it is a per-device opt-in.
- **Build the backend before the harness.** Rejected by the project owner's requirement: without a baseline, "better than CPAL" is an opinion.
